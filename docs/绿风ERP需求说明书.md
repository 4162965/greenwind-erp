# 绿风 ERP 管理系统需求说明书

> 文档版本：V1.0  
> 编制日期：2026-08-05  
> 文档状态：业务框架已确认，作为分阶段开发与验收依据  
> 适用范围：绿植租摆、室外养护、销售、换花、赠送、撤花、采购、仓储、配送、合同及项目财务管理

## 1. 建设目标

建设一套以“客户—项目—合同—订单—采购—仓库—配送/施工—项目植物—养护—费用结算”为主线的综合 ERP 系统，实现以下目标：

1. 统一管理客户、项目、员工、商品、合同、车辆等基础资料。
2. 覆盖租摆、销售、养护工程、换花、赠送、撤花和配送等业务。
3. 采购、仓储、派单和配送过程可追踪，并能准确归集项目成本。
4. 同一项目的多种业务可分别核算，也可合并查看整体收入、成本和利润。
5. 按员工角色控制功能、数据范围及金额信息的可见性。
6. 同时支持电脑端和手机浏览器使用，满足办公室和现场人员需要。

## 2. 总体业务主线

```text
客户
  → 项目
    → 合同
      → 业务订单
        → 审批（按规则触发）
          → 采购需求/仓库库存
            → 入库/备货
              → 排班与配送/施工
                → 项目植物与养护
                  → 项目成本、收入、应收、收款和利润
```

业务订单与执行任务分开管理：订单代表客户或项目业务，采购、入库、配送、施工和养护属于订单下面的执行环节。

## 3. 角色与部门

### 3.1 组织结构

员工拥有一个主部门、一个主职位，并可拥有多个业务角色。部门和角色均允许管理员自定义。

建议预设：

- 部门：市场部、绿化部、财务部、管理层等。
- 职位/角色：经理、主管、客服、采购员、仓管员、养护员、司机、跟车配送人员、财务等。

### 3.2 员工档案

所有员工均建立员工档案，但登录账号可选。员工档案至少包括：

- 姓名、手机号、部门、职位、业务角色。
- 入职日期、离职日期、在职状态。
- 负责项目、负责区域。
- 证件或其他附件。
- 是否启用系统登录。

离职员工停用账号，但历史业务记录永久保留。

### 3.3 数据权限

- 养护员：仅查看本人负责的项目、养护任务和换花单。
- 司机、跟车人员：仅查看本人被分配的配送任务详情。
- 客服：查看全部客户、项目、订单和执行进度。
- 采购员：查看采购需求和商品资料，不查看合同收入及项目利润。
- 仓管员：查看库存及出入库，不查看项目利润。
- 财务：查看合同、收入、成本、应收、收款及发票。
- 主管：查看本部门或负责范围内的项目和员工。
- 经理/老板：查看全部业务及经营数据。

养护员、司机、跟车人员等现场员工不得查看采购成本、销售价格、合同金额和利润。

当前基础版已实现订单与项目数据范围权限：客服、管理员、经理可查看全部项目和订单；主管可查看自己作为主管或客服负责的项目及其订单；养护员只可查看分配给自己的项目及其订单。员工档案可启用系统登录，默认用手机号作为账号，角色沿用员工角色；离职或关闭登录后账号自动停用。

## 4. 客户与项目管理

### 4.1 客户资料

一个客户可对应多个项目或服务地址。客户支持多个联系人，记录姓名、手机号、职务及备注。

### 4.2 项目资料

项目至少包括：

- 项目名称、所属客户、地址。
- 项目负责人及多个联系人。
- 主要业务类型：租摆、室外养护、临时销售等，可多选。
- 负责主管、客服、一个或多个养护员。
- 合同、项目植物、费用、订单及养护记录。

配送联系顺序：

1. 有养护员的项目优先联系相关养护员。
2. 项目负责人为第二联系人。
3. 销售等没有养护员的业务，以项目负责人或主要联系人为联系人。

### 4.3 项目位置层级

项目位置固定采用“楼层—区域”两级结构，不设置楼栋层级：

```text
金融中心项目
  → 8楼
    → 总经理办公室
      → 幸福树 × 1盆
```

同一位置、同一商品和规格的植物合并记录数量，例如“绿萝 × 10盆”。换花或撤花时，从该记录中选择需要处理的数量，不要求每盆植物单独编号。

### 4.4 多养护员管理

- 一个项目可分配一名或多名养护员。
- 多人项目可为养护员划分负责楼层或区域。
- 养护员可以只对本人负责区域提交换花或养护记录。

## 5. 商品与物料管理

### 5.1 商品分类

系统统一保留一个“商品”模块，通过分类区分植物、装饰花盆、农药、肥料、工具及其他物品。

商品至少包括：

- 商品名称、分类、图片和图片集。
- 采购单位和统一使用单位；统一使用单位同时用于商品显示、库存和项目使用。
- 动态规格、采购单位到统一使用单位的换算和商品价格。
- 采购价、销售价和月租价；采购价由相同商品规格最近一次采购入库单价自动更新。
- 启用状态和备注。

订单保存成交时的价格快照，后续修改商品参考价不影响历史订单。

### 5.2 动态规格

规格字段由用户自定义，可选择高度、粗度、冠幅或其他自定义名称；只显示已启用的规格项。

示例：

- 小发财树：230#、250#、280#。
- 天堂鸟：1.8M、2M。
- 其他植物可按高度、粗度、冠幅等组合设置。

规格可以设置独立图片；未设置时使用商品主图。

### 5.3 基地种植盆与装饰花盆

- 基地随植物提供的“福字盆大号、福字盆中号、紫砂盆、青龙盆”等属于植物规格，不作为独立装饰花盆库存。
- 项目使用的装饰花盆是独立商品，单独采购、入库、计价、出库和更换。
- 项目植物列表默认折叠装饰花盆信息，需要时通过开关展开。
- 支持只换花盆、不换植物；更换成本及货拉拉费用计入项目成本。
- 装饰花盆的大号、中号、小号分别建立为独立商品，各自维护库存、单独出库并归集项目成本。
- 花盆正常损坏通常由公司承担，客户收费默认为0。

### 5.4 成套采购商品

- 商品可开启“必须成套采购”开关，主要用于大号、中号、小号套盆。
- 开启后，商品主档代表整套采购单位，通常为“套”；规格行维护大号、中号、小号等可在项目中单独使用的型号。
- 项目、出库、换盆可以选择其中一个型号，例如只给项目换中号花盆。
- 采购需求只要涉及其中任一型号，就必须按整套采购，大号、中号、小号一起采购入库。
- 普通商品规格的采购价由最近一次采购入库价自动更新；成套采购商品的各型号采购价由人工按整套采购价拆分填写。
- 关闭开关后，各规格按普通商品处理，可分开采购、入库和出库。
- 不在商品模块处理“一箱转换成12盆”等通用包装换算；这类包装暂不登记为商品转换规则。

### 5.5 单位换算

单位换算暂不作为商品主流程登记。当前先统一按商品实际使用单位入库、出库和项目使用，后续采购模块如确需记录外包装，可作为采购备注或独立扩展处理。
- 农药：按箱采购，按瓶给项目。
- 肥料：按袋采购，按斤给项目，允许小数。

系统不登记员工个人或随车库存；相关人员上报项目所需数量，公司按量配送到项目。

### 5.6 单位设置

- 平台设置中提供单位管理，可新增、删除和恢复默认单位。
- 商品新增、编辑时的单位下拉框读取平台设置中的单位列表。
- 成套采购开启时，整套采购单位默认“套”，型号单位默认“个”。

### 5.7 组合盆景

- 多个小植物可与装饰花盆组合成一个盆景后送到项目。
- 支持常用组合模板和临时自定义组合。
- 成品成本为植物、花盆及其他组件成本之和。
- 项目列表主要显示组合成品，可展开查看内部组成。

### 5.8 批次成本

- 实际采购价格可因供应商、日期和季节变化。
- 商品采购价显示相同商品规格最近一次采购入库价，项目实际成本使用真实采购批次价格。
- 项目专项采购绑定实际批次成本。
- 公司公共库存默认按先进先出计算，仓管员可按权限选择具体批次。

## 6. 合同管理

### 6.1 合同结构

- 一个项目可有多份合同。
- 支持整体合同和分体合同。
- 一份合同可以覆盖一个或多个业务类型。
- 续签合同、补充协议需关联原合同。
- 保存合同编号、期限、金额、计费方式、付款周期、附件、状态及提醒设置。

### 6.2 费用与计费

- 支持月、季度、半年、年、一次性及自定义付款周期。
- 自定义分期可手工填写每期日期和金额。
- 租摆或养护费用可以固定，也可以因植物增加、减少等情况调整。
- 系统可按明细计算参考金额，主管或经理可根据与甲方协商结果填写最终金额。
- 调整支持按月、按天折算、一次性议价或直接填写确认金额。
- 默认从合同生效日开始计费，客服或主管可按合同约定修改计费开始日期，并记录原因。

### 6.3 合同提醒

合同到期提醒可自定义提前天数、重复方式及接收员工或角色。

## 7. 项目植物管理

项目植物记录至少包括：

- 项目位置、植物、规格和数量。
- 可折叠的装饰花盆信息。
- 来源：新采购、仓库库存、买断上一家、其他。
- 负责养护员及负责区域。
- 入场日期、计费开始日期、状态。
- 相关订单及变更历史。

植物来源在项目进场前统一选择一次（如新采购、仓库库存、买断上一家等）。以后继续增加该项目的植物清单时自动继承项目来源，不要求逐条重复选择。

员工现场盘点后，将结果告知客服或主管，由客服或主管录入正式项目植物数据；普通现场员工不得直接修改正式项目植物台账。

## 8. 订单体系

系统订单类型包括：

1. 租摆订单。
2. 销售订单。
3. 养护工程订单。
4. 换花单。
5. 赠送单。
6. 撤花单。
7. 配送任务/配送单。
8. 每日安排表。

订单公共能力包括：项目、联系人、商品清单、位置、费用方式、配送方式、执行进度、附件、操作记录和关联单据。

当前基础版已实现统一订单底座：租赁订单、销售订单、换花订单、养护订单和配送订单共用“订单主表—订单明细”结构，支持新增、编辑、列表查询、商品/规格明细、位置说明、是否需要采购、是否需要配送和状态流转。后续采购需求、出库单、配送排班、审批和项目成本将基于该订单底座继续串联。

当前基础版已实现订单联动：订单可一键生成采购单或出库单。生成采购单时使用订单商品明细和最近采购价形成待采购明细；生成出库单时使用订单商品明细和成本价形成待出库明细。重复点击不会重复生成单据，会返回已有的关联单号。

## 9. 租摆业务流程

### 9.1 新采购进场

```text
客服建立租摆单
  → 审批（如规则触发）
  → 采购需求
  → 采购员买货
  → 仓管入库
  → 客服安排车辆、司机和跟车人员
  → 配送至项目并按位置摆放
  → 客服或主管确认“已按位置摆放完成”
  → 主管委派养护员
  → 项目进入日常养护
```

大项目允许分多次采购、入库、配送和摆放，可使用不同日期、车辆和人员。司机只能更新运输环节状态，最终摆放完成必须由客服或主管确认。

### 9.2 使用仓库库存

有可用库存时跳过采购，直接预占库存、排班、自动出库、配送和摆放。

### 9.3 买断上一家植物

- 买断通常只谈项目整体总价，不拆分单株价格。
- 仅产生一次性买断成本。
- 员工到现场盘点后，由客服或主管录入植物、数量和位置。
- 不经过采购、入库和配送流程。
- 主管分配养护员后完成进场。

## 10. 换花与换盆流程

### 10.1 同品种更换

植物死亡或状态不佳时，养护员可直接选中原项目植物，申请更换相同品种和规格。

### 10.2 更换品种

更换其他品种必须由区域主管直接建立换花单：

```text
区域主管下单
  → 客服接单
  → 审批（如触发）
  → 采购/仓库/配送
  → 完成更换
```

### 10.3 旧植物和退货处理

- 正常死亡、状态不佳的旧植物默认丢弃，不要求每次选择去向。
- 撤花单中的植物和装饰花盆也默认丢弃。
- 新采购货物因规格错误或人为原因退回时，默认全部退回公司，再由公司决定入库、退供应商、调拨或报损。
- 特殊情况允许人工修改处理方式，并保留记录。

### 10.4 只换花盆

允许植物不变，仅更换装饰花盆；项目植物记录只更新花盆，花盆采购价及相关运输费用计入项目成本。

## 11. 撤花流程

```text
区域主管建立撤花单
  → 客服接单
  → 客服派单
  → 司机及配送人员到项目撤花
  → 确认完成
```

撤花可针对单个位置的部分数量、某层、某区域或整个项目。完成后同步减少项目植物数量或结束相应记录。

## 12. 销售与赠送

### 12.1 销售单

```text
客服/主管建立订单
  → 审批（如触发）
  → 检查库存
  → 缺货则采购
  → 入库或供应商直送
  → 配送/客户自提
  → 完成并确认收入及成本
```

### 12.2 赠送单

赠送单流程与销售类似，但收入为0；必须记录成本、赠送原因及接收对象。是否审批由自定义规则决定。

## 13. 养护工程与室外服务

服务类型可包括修剪、打药、施肥、补种、除草、清理、工具或药品配送等，并允许自定义。

执行方式包括：

- 公司员工现场处理。
- 客户自行处理。
- 外包或临时工处理。
- 采购后通过货拉拉或快递直送，不安排公司配送人员。
- 无采购的纯人工服务。

费用方式包括：合同内包含、合同外收费、客户承担材料、公司免费、客户自行处理、待协商。默认整张订单使用一种费用方式；少量特殊订单可开启“按明细分别设置”。

养护员、客服、主管和经理可按权限建立服务单。

## 14. 配送方式与任务进度

所有相关订单统一支持：

- 公司车辆。
- 货拉拉。
- 快递。
- 客户自提。
- 供应商直送。
- 无需配送。

货拉拉、客户自提及供应商直送可按实际情况跳过司机或仓库环节，由客服根据反馈确认完成。相关人员只能查看本人订单或任务的处理进度，主管和客服可查看负责范围的完整进度。

## 15. 每日排班与车辆管理

### 15.1 排班规则

- 客服通常安排第二天的工作。
- 不设置默认司机，客服根据实际情况为每次任务安排车辆、司机和跟车人员。
- 同一车辆一天可服务多个项目；一个项目也可使用多辆车。
- 系统检查车辆、司机和人员的时间冲突。

### 15.2 每日安排表

安排表至少显示日期、路线、车辆、司机、跟车人员、项目、任务、植物清单和状态。

- 草稿仅客服、主管和经理可见。
- 发布后所有员工可查看当天完整安排表。
- 被分配任务的详细内容仅相关人员可查看和更新。
- 排班表不显示成本和财务信息。
- 已发布安排仍允许修改。
- 修改后产生新版本，突出显示变化并提醒受影响人员。
- 支持改日期、路线、车辆、人员、数量、取消任务或改为货拉拉。

### 15.3 车辆档案

记录车牌、车型、状态、保险、年检、维修、保养和附件。提醒可设置提前天数、重复方式及接收人或角色。

## 16. 采购管理

当前基础版已实现采购单列表、新增/编辑采购单、采购明细、实际单价、运费/货拉拉费用、确认入库。确认入库后会更新对应商品规格库存和最近采购入库价。
确认入库同时生成库存流水，记录商品、规格、数量、入库前库存、入库后库存、采购单号、采购员和金额。

### 16.1 标准流程

```text
采购需求
  → 审批（按规则触发）
  → 合并采购
  → 分配采购员
  → 填写实际商品、规格、数量和采购价格
  → 入库或直送
  → 记录运费、货拉拉等附加费用
  → 完成
```

### 16.2 合并采购

多个项目、多个订单的采购需求可以合并为一张采购单，但系统必须保留每一条需求的来源、项目、订单和数量分配，以便后续准确归集成本。

### 16.3 实际采购规格

采购员可根据市场实际情况直接按可采购的规格供货，无需主管再次确认。系统同时保存原需求和实际采购内容，并将实际规格通知客服；后续入库、配送、项目植物及成本均使用实际采购内容。

采购员可填写实际商品、规格、数量、单价、供应商、采购日期和附加费用。

## 17. 仓库与库存

### 17.1 仓库范围

- 系统始终只有一个仓库。
- 暂不进行库位、货架或仓区管理。
- 显示现有、可用、预占、在途、待入库、待出库、损坏及批次成本。

### 17.2 入库

- 仓管员必须确认入库。
- 入库记录实际商品、规格、数量、单位换算、实际采购价和批次。

### 17.3 出库

- 保留出库单和出库记录。
- 默认不要求仓管员确认。
- 创建配送任务时预占库存。
- 公司车辆由司机确认“已出发”时自动正式出库并扣减库存。
- 货拉拉或客户自提由客服确认已发货后扣减库存。
- 供应商直送不进入公司库存。
- 未来可为个别商品开启“出库需要仓管确认”，默认关闭。

### 17.4 当前基础版实现

- 已实现库存盘点页面，可按商品、规格和成套采购查看当前库存。
- 支持按商品名称、编码、分类搜索，并可筛选零库存/缺货商品。
- 支持仓管手工盘点调整库存；每次调整生成库存流水。
- 库存流水记录采购入库和盘点调整，包含变化前库存、变化后库存、数量、单位、来源单号、操作人和备注。
- 已实现出库单基础版，支持项目领用、销售出库、换花出库、赠送出库、撤花报损和其他出库。
- 出库单确认后扣减对应商品或规格库存，并生成出库方向的库存流水；库存不足时不允许确认出库。

## 18. 养护管理

### 18.1 养护计划

每个项目支持：

- 固定日期，如每周二、周五。
- 固定次数，如每月8次，日期灵活安排。
- 主管临时增加任务。

系统自动生成养护任务。养护员查看自己的任务，主管查看全部项目的计划数、完成数、未完成和逾期情况。项目更换养护员后，未完成任务可批量转给新养护员。

逾期天数、接收人和重复提醒方式允许自定义。

### 18.2 日常养护记录

记录项目、负责区域、到场日期、工作内容、现场问题、处理结果、照片、客户备注和下次计划日期。可从养护记录直接生成换花、换盆、采购或施工任务。

第一阶段不强制GPS定位，签到和照片为可选；网络不稳定时允许先保存草稿。

### 18.3 月度养护报告

项目可选择是否启用月度报告。报告自动汇总养护日期、养护员、工作内容、计划与完成次数、换花/换盆/修剪/打药记录、现场照片、未解决问题及下月建议。

养护员原始记录不得由客服直接修改；客服只能补充对客户说明。需要改正原记录时，由主管退回养护员修改。

## 19. 审批机制

### 19.1 通用能力

- 审批规则可新增、启用、停用和修改。
- 支持指定具体员工或角色。
- 支持单人审批、多人任一人通过、多人全部通过及逐级审批。
- 未命中规则的业务直接进入下一流程。
- 驳回必须填写原因，修改后可重新提交。
- 审批通过后如修改关键金额、数量、商品、项目或费用承担方式，应重新审批。
- 项目未单独设置审批人时，使用公司默认审批流程。

### 19.2 合同年度换花额度

- 每个项目可设置换花成本审批额度。
- 额度按关联合同的合同年度累计，不按自然年或自然月。
- 默认关联租摆合同；没有租摆合同或存在特殊情况时，由主管选择“换花额度所属合同”。
- 合同年度示例：合同生效日为2026-04-15，则第一年度为2026-04-15至2027-04-14。
- 每个新合同年度重新累计，历史年度保留。
- 预计采购单价取相同商品、相同规格最近一次采购入库价。
- 没有历史入库价时按0元估算，允许直接提交。
- 当前换花单使累计成本超过额度时触发审批；超过后，该合同年度内后续换花单均需审批。
- 实际采购入库后，以实际价格更新累计换花成本。

### 19.3 项目全部采购审批

项目可开启“所有采购需求必须审批”。开启后，该项目任何采购需求无论金额大小，均需审批通过后方可采购。

## 20. 项目工资与人工成本

- 主管直接填写每名养护员在每个项目的月工资。
- 同一养护员负责多个项目时，分别填写各项目工资。
- 项目工资按月计入对应项目成本。
- 下月默认沿用上月金额，主管只修改发生变化的数据。
- 中途换人、请假或不足整月时，主管可填写当月实际金额并注明原因。
- 历史月份结算后不受以后调整影响。
- 财务可查看、复核和调整。
- 司机和跟车人员工资属于公司公共成本，不计入单个项目。
- 临时工按实际金额、日期和工作内容计入单一项目。
- 主管填写的是项目工资，不要求按员工实际总工资自动分摊。

## 21. 财务、应收与发票

### 21.1 应收、收款和发票

应收、收款、发票三类记录相互独立并支持多对多关联：

- 可先开票后收款，也可先收款后开票。
- 支持分次开票、分次收款。
- 一张发票可对应多期费用。
- 一笔收款可分配到多个项目、合同和应收期次。
- 尚未分配的收款作为客户余额或待分配款保留。

### 21.2 两套经营口径

1. 经营利润：按确认收入减项目实际成本，用于判断项目盈利能力。
2. 现金收支：按实际收款减实际付款，用于查看现金回收情况。

老板首页默认显示经营利润，现金收支单独查看。

### 21.3 报表维度

- 按日、周、月、年、合同周期查看。
- 按项目整体查看。
- 按租摆、室外养护、销售等业务类型分别查看。
- 多业务合并查看。
- 显示收入、成本、利润、利润率、应收、已收及欠款。

### 21.4 成本确认时间

- 项目专项采购直送：确认送达时计入项目成本。
- 采购进入仓库：入库时形成库存，不计项目成本；出库给项目时计入。
- 换花、花盆、药品和工具：实际配送或领用到项目时计入。
- 养护员项目工资：按所属月份计入。
- 临时工和外包：按实际施工完成日期计入。
- 货拉拉、快递等费用：跟随对应采购、配送或服务单计入。
- 买断上一家植物：按约定日期一次性计入项目成本。
- 取消或退货：通过冲销记录冲减原项目成本。

### 21.5 收入确认时间

- 租摆、室外养护等周期业务按合同计费周期逐月确认。
- 当月植物增减或金额调整，由客服或主管确认当月实际计费金额。
- 销售单完成时确认收入；赠送单收入为0。
- 临时收费服务完成并确认收费金额后确认收入。
- 收款日期仅影响现金收支及欠款，不改变经营收入所属月份。
- 退款、减免或作废通过冲销单处理，不删除原收入记录。

## 22. 消息与待办

第一阶段仅提供系统内消息，不接入短信或微信。提醒范围包括：

- 待审批、审批通过或驳回。
- 新任务、改派和排班修改。
- 采购待处理、入库待确认。
- 配送临近及配送方式变化。
- 养护任务即将到期或逾期。
- 合同、车辆保险和年检到期。
- 应收款到期或逾期。
- 库存不足。
- 换花成本接近或超过合同年度额度。

员工首页只显示与本人有关的待办；主管和经理可查看负责范围内的逾期事项。提醒允许设置接收人、提前天数和重复方式。

## 23. 操作日志与数据安全

- 订单、采购、库存、合同、项目工资、收付款等关键数据不得直接删除，只能作废或冲销。
- 记录新增人、修改人、时间及修改前后内容。
- 金额、数量、审批人、项目、商品等关键变化重点标记。
- 已结算月份默认锁定，仅财务或经理可解锁。
- 权限变化、账号登录、审批和财务数据导出均记录日志。
- 支持按日期、员工和业务单号查询。
- 支持定期自动备份及管理员手动备份。
- 普通员工不能查看完整日志；主管查看负责项目；管理员和经理查看全部。

## 24. 终端与使用方式

第一阶段采用响应式 Web 系统，不单独开发安卓或苹果 App。

- 员工使用手机号和密码登录。
- 网页可添加到手机桌面。
- 养护员手机首页突出今日养护、项目植物、换花报单和养护记录。
- 司机/跟车人员突出今日配送、地址、联系人、清单和进度。
- 主管/客服可在手机查看排班、审批和订单进度。
- 财务、采购和仓库复杂操作优先适配电脑端。
- 手机端按权限隐藏金额和成本。
- 网络不好时允许保存草稿，恢复网络后提交；第一阶段不做完整离线功能。

## 25. 明确不纳入当前范围

以下功能当前不建设：

- 客户反馈、投诉与回访独立模块。
- 强制GPS定位打卡。
- 员工个人库存或随车库存。
- 多仓库、库位和货架管理。
- 独立安卓或苹果 App。
- 第一阶段的短信、微信通知。

客户临时需求由客服直接建立相应订单或任务。

## 26. 分阶段开发计划

### 第一阶段：基础档案

- 客户、项目及项目位置层级。
- 员工、部门、角色及权限。
- 商品、动态规格、图片、单位换算和价格。
- 合同和项目植物。
- 养护员项目工资。

### 第二阶段：核心订单

- 租摆、换花、撤花、销售、赠送和养护工程订单。
- 统一订单状态和关联单据。
- 分批执行和完成确认。

### 第三阶段：采购与仓库

- 采购需求、合并采购、实际规格与价格。
- 入库、库存预占、批次成本和自动出库。

### 第四阶段：配送与排班

- 多种配送方式。
- 车辆、人员和次日安排表。
- 发布、修改、版本和冲突检查。

### 第五阶段：养护管理

- 养护计划、任务、日常记录。
- 养护记录转换花或服务任务。
- 项目月度养护报告。

### 第六阶段：审批与财务

- 自定义审批。
- 合同年度换花额度和项目采购审批。
- 应收、收款、发票、项目成本和利润。

### 第七阶段：系统完善

- 消息待办、操作日志和数据备份。
- 手机端优化和综合经营报表。

## 27. 开发与验收原则

1. 每个阶段先完成数据结构和基本操作，再串联业务流程。
2. 每个功能必须进行本地测试，包含正常流程、异常流程和权限测试。
3. 金额、库存、项目植物数量和状态变化必须可追溯。
4. 任何历史业务不得因修改商品、员工、合同或价格而被覆盖。
5. 新需求优先通过自定义分类、规格、角色、审批规则和提醒配置实现。
6. 每完成一个阶段，在本文档中补充完成状态、测试结果和待处理问题。
