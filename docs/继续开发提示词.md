重要约束：
- 不要随便删除真实数据。
- 不要把测试数据直接提交到 GitHub，除非用户明确要求。
- 新增或修改功能后，要先本地构建/测试，再提交 GitHub。
- 如果页面打不开，先检查后端是否启动、前端 API 是否请求到了正确 IP/端口，不要盲目改业务代码。
- 所有日期选择要中文显示。
- 订单、采购、入库、配送要按流程状态流转，不要只是生成孤立单据。
- 操作按钮尽量统一收进“更多”或按状态显示主按钮，表格操作列固定在最右侧，少占位置。
- 手机端不是电脑端自适应，而是独立手机页面，入口 /mobile。

下一步优先开发建议：
1. 从完整业务流程继续打通：
   养护员手机报换花单
   → 客服在电脑端看到待处理订单
   → 点击采购，优先匹配库存
   → 缺货生成采购单并跳转高亮
   → 采购填写采购价、上传收据和商品详情
   → 仓管确认入库
   → 客服安排配送，选择车辆、司机、跟车人员
   → 每日安排表按日期、车辆、司机、跟车人员、项目、植物明细合并显示
   → 配送完成后订单状态完成。
2. 检查每类订单状态是否统一：
   待采购、采购中、待入库、待配送、配送中、完成、取消。
3. 检查所有列表页表头设置、状态分类、批量选择是否统一。
4. 检查手机端工作台入口是否和电脑端模块对应。
5. 再做细节 UI 优化，不要先大改架构。
